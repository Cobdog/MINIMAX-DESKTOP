# devdocs MANIFEST — the tech-reference capture registry

`docs/devdocs/` is the local, refreshable, primary-source TECH reference home (generalizes `docs/library/`, which stays the DOMAIN-research capture home). Protocol, compact:

- **Scope:** every mission-critical framework/library/system/API we integrate against. One directory per tech (`<tech>/index.md`, + verbatim captured pages with provenance headers when a doc page is the source).
- **Every capture carries:** source path/URL, pinned/verified revision, fetch date, license note, a "local reliance" line (what in OUR tree depends on it), and verify-on triggers. License discipline identical to the library: **internal reference only — never shipped, never vendored** (GPL-3.0 / no-license sources are read here, never redistributed).
- **Freshness = this manifest + triggers.** On a trigger, run the library's SOURCE-OF-TRUTH three-question check (changed? superseded? impossible-become-possible?) against the live source and record a DATED ADDENDUM in the capture — never silent replacement of the frozen body. A quarterly sweep is one Flux task re-checking the most load-bearing rows.
- **Budget:** 3–5 captures per pass (the library rule) — grows opportunistically as work touches new tech.
- **Priority inventory still to capture** (from the direction audit's Part 4): better-sqlite3+FTS5, zustand, d3-zoom, react-rnd (or successor per DA-5), @base-ui/react, ws+SSE semantics, vite/vitest, Playwright, pino → llama.cpp server API, ffmpeg, @huggingface/transformers → three, the trainers (Fizgig/Musubi/Ostris — mandatory BEFORE the workbench build), Node worker-threads (if A-7 adopts).
