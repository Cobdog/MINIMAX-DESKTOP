## 1. Phase 1 — the blind walk (stock H3 engine)

The journey as walked: boot → wizard → engine dead → honest refusal → engine up → wizard GONE → prompt → auto-rendered video chain → settings end-to-end → global+chain overrides with graph-level verification → image workbench packet → pin to canvas → reference bind → break-things (hang, engine death, validation rejection) → recovery → library/fetch surface.

**What genuinely works (the spine is real):**

- **The render loop, end to end.** Prompt → submit → live progress (10 steps, %, binary PNG previews on the tile) → `executed` → media landing on the card (`MEDIA · 5.0S · DECODED`), takes recorded with canonical/restore semantics, play/ops/fork available. Verified three times across two engine profiles.
- **Crash recovery is the best surface in the app.** Engine killed mid-render: card shows "Waiting for ComfyUI to start", badge flips to `engine offline` within one 15 s probe cycle with an assertive "Start ComfyUI and verify the server connection in Settings." On restart: *"Engine connected — node registry and model inventory re-synced."* — and the orphaned job is failed with a precisely-worded reason: *"The generation engine restarted mid-render and the fresh instance no longer knows this prompt (it was unreachable when the work was lost) — the render did not complete. Re-run this chain."* The "1 needs attention" header state + `calm` button complete the arc.
- **The override resolution chain is CORRECT at graph level.** Verified by inspecting the graphs the engine actually received: global pick (FL2VA lane → ref2va file) landed in `UNETLoader.unet_name`; a chain pick then beat it (fl2va file). Chain > global > auto, exactly as documented. Slot-level attribution in the chain panel works too (`auto — global: <file>`).
- **Registry-only inventory holds.** Every picker lists exactly the engine's `/models` registry rows (subpaths included); the graph receives the engine-relative subpath verbatim. No path fields anywhere. The pack board's key-presence detection is honest (see §3 R-12).
- **The image workbench packet pipeline works.** 5-frame packet → take strip → the first-party scorer ran on the landed frames and marked its pick ("sharpest of the pool (Laplacian 0.3)") → Pin frame / Start-frame exit enabled. Refine/Burst honestly disabled with reasons ("The affordance says so — never a silent skip").
- **References bind end to end.** Pinned frame → consume-from menu on a video chain → `Add as reference` → `1 of 9 slots · <Picture 1> · Canvas reference: workbench-frame-4.png`, chain flips to `reference → video`, and the submitted graph carries `LoadImage` + `MiniMaxH3ReferenceToVideo`.

**What the walk found broken, confusing, or lying (numbered for the punch list):**

Code-confirmed root cause — `src/canvas/FirstRunWizard.tsx:120`: `if (!context || !sawScan || scanning || models.length > 0 || state.done || state.skipped || !settings) return null` — the wizard only renders while the registry is EMPTY. A user whose engine is already running at boot never sees the wizard at all; a user mid-wizard loses it the instant connection succeeds. - **F2 — the H3 stack table says FL2VA is MISSING while the pickers on the same screen infer it.** Settings → Status & diagnostics → "H3 engine stack": `FL2VA — Missing · expected minimax_h3_fl2va_pruned_int8_convrot.safetensors — MISSING`, whole table `INCOMPLETE` — while the model-override pickers directly above show `auto (inferred) — H3/ssd/minimax_h3_fl2va_pruned_int8_convrot.safetensors`. ## 2. Phase 2 — the mirror walk (the maintainer's instance shape)

Profile `maintainer-instance` (see `e2e/mirror/profiles/maintainer-instance.json`): fl2va_pruned + ref2va + music3 at `H3/ssd/`; text encoders `qwen3vl_32b_minimax_h3_nvfp4_awq` AND `qwen3vl_4b_minimax_h3_int8` (the wrong-pick trap); VAEs under `h3image/` subdirs AND at root; `vae_approx` with the taeh3 files; loras = official turbo 8 + a multishot adapter; pack classes PreviewOverride(+CS), one-node, multishot, lora-manager, VHS.

The toast says "model inventory re-synced"; the pickers say otherwise. **On the maintainer's box: every ComfyUI restart with changed models leaves the studio on the old registry until a manual Settings refresh.**

Suspected seam: `h3PreviewOverrideNode` rides the canvas store's `facts` snapshots (`store.ts:1185/1598/1670/2579`) which did not re-derive across the engine-restart/settings-refresh transition — the same staleness family as M1 — or the routing requires `selection.previewVae` which resolves only for exact `taeh3_decoder.safetensors`/`taeh3.safetensors` basenames plus a `taeh3`-substring fallback (`modelSelection.ts:99`); the mirror's `taeh3_alpha*` names should match the fallback, pointing harder at the facts-staleness seam. Needs a precise root-cause pass (CPU-only); the audit records the observed gap against the claim.
- **M7 — end-to-end render WORKS on the mirror inventory** (the reference render completed and landed after refresh). The maintainer's model set is fully servable by the current graphs.

## 4. Phase 4 — the punch list, ranked by JOURNEY impact

The maintainer's stated top goal: **image generation working**; then model selection making sense on THEIR inventory. Rank follows their journey, not severity taxonomy. "Fix shape" names the suspected code seam; CPU-only = no GPU needed to fix and verify (fake engine + this mirror profile re-run).

Root cause: `h3Stack.ts` exact+anchored-regex match against the subpath instead of the basename. Fix shape: compare `basenameOf(model.name)` (the pickers already do); CPU-only; one file + a fixture with `H3/ssd/` paths.
2. **Engine restarts leave the model registry stale while the toast claims a re-sync** (M1/C1). Wrong-registry preflights and pickers until a manual refresh. Fix shape: pass `{refresh:true}` on the recovered transition (or bust the server cache on recovery); CPU-only.
3. **The PreviewOverride pack never takes over previews on the mirror** (M6/C7). The maintainer-endorsed fix for the fragile stock taeh3 prefix-match class is not engaging in practice. Fix shape: RCA the `h3PreviewOverrideNode` facts derivation across engine transitions (suspected: canvas store facts not re-derived on reconnect; also confirm `previewVae` fallback matching for `taeh3_alpha*` names); CPU-only to diagnose and fix against the mirror.
4. **The image lane dead-ends and mislabels** (F6/F8/M5): no lane toggle after the first chain; pinned frames become T=1 chains that cannot generate on their inventory; image chains labeled "text → video". Fix shape: lane toggle on the footer bar (or explicit lane in the spawn flow); pin creates a plain media object by default with image regeneration as the explicit opt-in; fix the mode label; surface the Mamad8 requirement at PIN time, not generate time. UI/CPU-only except the 4.85 GB Mamad8 fetch itself (maintainer's call; the catalog row exists).
5. **Music 3's audio-VAE inference is blind to their audio VAE** (F3/M4). Fix shape: product decision — accept the H3 audio VAE file in the music3 ladder, or label the slot "requires the music3 DAV file" so "nothing detected" reads as a requirement, not a bug; CPU-only.
6. **`[redacted]` still reaches users** (F11/C2) — the Wave-1 bar, verbatim-unsatisfied. Fix shape: structural join of engine validation messages without the sanitizer's mid-token strips (or sanitize-then-render with the type tokens inline); CPU-only.
7. **"fetch missing (8)" points at a catalog without the rows** (F10/C6). Fix shape: add the turbo LoRA weight rows to `fetchCatalog.ts` (license verdicts per row) or reword the affordance to the truth; CPU-only.
8. **The chain MODELS header chip lies about attribution** (F4/F5/C4). Fix shape: derive the chip from the resolved layer (chain pick / global pick / auto) — the data already exists at slot level; CPU-only.
9. **The wizard's steps 2–4 are unreachable** (F1/C5). Fix shape: visibility keyed on wizard completion (`done`/`skipped`), not registry emptiness; CPU-only.
10. **Polish tail, one sweep**: literal `{effectivePick + 1}` (F7); `h3img N` vs `image N` naming (F8); unavailable-tooltips leading with the already-installed pack (F9); raw JSON in the Manager note (F12); cross-class options unmarked in pickers (M3 — at minimum a class glyph or grouping); "17n+5" jargon hints (C11); seed spinbutton a11y `valuemax` (F14); the visual-only duplicate tier chip (V1) and the clipped toast pill (V2); the low-contrast/small-type legibility tail (V3). All CPU-only.
