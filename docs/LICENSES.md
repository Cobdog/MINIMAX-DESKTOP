# Third-party license inventory

> **What this file is:** the point-in-time, machine-checkable inventory of every
> third-party component this project consumes — code dependencies, vendored
> packs, user-fetch-only components, and model weights — with the SPDX verdict,
> how we consume it, and the obligations it triggers.
> **Why a separate file:** [PROVENANCE.md](PROVENANCE.md) records who *we* are
> licensing-wise (AGPLv3 rationale, fork lineage, distribution policy);
> LICENSES.md records what *we ship*. Cross-linked so either is a valid entry
> point.
>
> **Regeneration:** `pnpm license:audit` (gate + CI) re-derives §1 from
> `node_modules` manifests, re-checks that every vendored pack ships its LICENSE
> file, and enforces the §3 license gate (never vendor what we can't ship).
> After dependency changes, paste its table output back into §1.

## 6. AGPLv3 compliance mechanics

- **LICENSE at repo root** — full AGPLv3 text `[LOCAL]`.
- **README → License** — license statement, fork-lineage pointer, source offer
  (§13), and a pointer to this inventory.
- **In-app notice** — Settings → "License & source" (always visible, not
  dismissible): app license + canonical source link. The one-time
  `LicenseNotice` component is a *different subject* — the MiniMax model
  license — and stays as is; two notices for two licenses, deliberately not
  conflated.
- **§13 network interaction** — the server serves the web app over HTTP, so
  remote users are network users. Since the app is distributed as source and
  run by its own operator, the Corresponding Source for an unmodified
  deployment is the repository itself; operators of modified copies point
  theirs at their fork (README + Settings carry the canonical URL). There is
  no binary distribution today, so no separate written-offer machinery is
  needed.
- **Upstream ARR conflict** — the fork-lineage position (machine-generated
  upstream, independent rewrite) is recorded in
  [PROVENANCE.md](PROVENANCE.md) with its IANAL caveat; nothing mechanical to
  add. If upstream ever asserts, the recorded resolution path is completion of
  the rewrite.

## 7. Headers policy — recommendation (maintainer to decide)

Per-file headers were **deliberately deferred** when AGPLv3 was adopted; this
section is the promised options memo. Default until the maintainer picks:
**keep the current no-headers stance.**

| Option | What | Strengths | Costs |
| --- | --- | --- | --- |
| **A. Status quo** (recommended default) | root LICENSE + README + Settings notice + this inventory + `pnpm license:audit` as the SPDX manifest | zero friction; how most of the npm ecosystem ships | a file copied out of the repo carries no license line of its own |
| **B. SPDX line per file** | `// SPDX-License-Identifier: AGPL-3.0-or-later` as line 1 of every source file | machine-checkable (reuse.software tooling); travels with every file; one line, no boilerhead | one codemod + a lint rule to keep it true on new files |
| **C. Full GPL-style header blocks** | traditional license + copyright header per file | maximal traditional signaling | noisy, merge-churn, redundant with the root license |
| **D. NOTICE file** | root `NOTICE` consolidating third-party attributions (Apache §4 hygiene) | single place auditors read; future-proofs a bundled dist | another file to keep in sync (could be emitted by the audit script) |

## 8. VDN LongCache patch — distribution analysis (flagged for maintainer sign-off)

**The question.** `server/enginePatch.ts` ships a patcher whose content
constants (`RUN_BLOCKS`, `HOOK_LOOP`) are a verbatim port of the maintainer's
own fork installer (ComfyUI-VDN-H3-24GB, Apache-2.0), applied at runtime —
with recorded consent — against `comfy/ldm/minimax/model.py` in **ComfyUI, a
GPL-3.0 program**. Does shipping this create obligations for our AGPLv3
codebase?

**Analysis.**

1. *The tool vs the patched program.* GPL obligations attach to
   **conveying** copies. We convey the patcher; we never convey ComfyUI, a
   pre-patched ComfyUI file, or even a patch/diff carrying ComfyUI context
   lines. The modified `model.py` exists only on the user's machine, produced
   by the user's consented action on the user's own checkout — GPL §0/§9
   leave modification of one's own copy unrestricted. This is the
   ComfyUI-Manager-class pattern the ecosystem treats as the sanctioned way
   to touch core.
2. *Is the patcher a derivative of ComfyUI?* The layout regexes encode
   structural facts (a call sequence), not literal expression. The constants
   are literal text — the honest crux, with two readings:
   - **(a) Apache-2.0 reading:** the fork's author re-implemented the loop and
     licensed it Apache-2.0 → our port is plain Apache-2.0 inclusion; §4
     duties (retain notices, state changes) are met by the in-file attribution
     and this record.
   - **(b) GPL-3.0 reading:** `RUN_BLOCKS` "mirrors the upstream loop exactly
     plus slicing" — if it is substantially copied from ComfyUI's own loop,
     the fork's Apache-2.0 grant is ineffective for that copied portion (a
     licensee cannot relicense the licensor's code) and those ~45 lines remain
     GPL-3.0 in origin. GPL-3.0 and AGPLv3 are explicitly
     combining-compatible (GPLv3 §13, final paragraph) and our app already
     accepts §13 network terms globally, so the repo remains distributable
     under AGPLv3 with those lines carrying GPL attribution duties (credit
     ComfyUI for the loop text).
   Either reading yields the same conclusion: **no blocker, only attribution.**
3. *Residual duties we already meet:* never distribute a pre-applied patch
   (the patcher is the only distribution form — keep it that way); the consent
   gate + pristine-backup revert keep the user's modified copy inspectable and
   reversible; attribution records live in `server/enginePatch.ts`'s header
   and here.

**Verdict:** no obligations are created for the AGPLv3 codebase beyond
attribution and the never-distribute-pre-applied rule we already follow.

**Options** (legal-adjacent judgment — maintainer sign-off requested; the
PROVENANCE IANAL stance continues):

1. **Status quo + documentation (recommended):** patcher ships as code,
   applies user-locally only, consent-gated, reversible; attribution as
   recorded. Cost: none. Risk: reading (b) stays theoretically open — and is
   harmless per §8.2.
2. **Independent re-implementation** of the constants from ComfyUI's published
   behavior (not porting the fork's text): removes reading (b) entirely;
   costs re-validation of the patched layouts.
3. **Upstream the `("block_loop", 0)` extension point to ComfyUI core:** kills
   the entire question on any version that has it (our version gate then
   degrades the patcher to unused). Best long-term engineering outcome too.

*Post-rewrite cross-check (2026-09-17, task 68rnn84): analysis unchanged and
still accurate — `server/enginePatch.ts` survived the canvas rewrite intact
(patch constants and attribution header verified present in the tree); the
verdict and the option pick remain staged with the maintainer.*
